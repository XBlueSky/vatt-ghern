# Impeccable — Design Context for vatt-ghern

## Design Context

### Users

**Primary**: Tony Hu — Synology engineer who runs daily tech-news triage
through a Claude routine. He opens the site daily to scan today's roundup
(3-minute read) or drill into one of today's deep-stories (5-15 min). He
already knows HTTP, TCP, threads, SQL, kernel — does not want explanations
of basics.

**Secondary**: Engineers who follow shared links. Task-driven arrivals —
they came for a specific RFC, CVE, or design teardown. They will give up
fast if the site looks unserious or makes them work to read.

Context: people read on laptops in early morning (coffee in hand) or on
phones during transit. Both light-mode commute reading and dark-mode
desk-at-night reading need to work without strain.

### Brand Personality

**Three words: measured, curious, materially-rooted.**

- **Measured** — findings stated plainly, hedges honest ("the proposal
  looks promising but the benchmark methodology is suspicious"). No
  breathless hype, no "you won't believe X."
- **Curious** — investigative posture. Articles open with a question or
  an anomaly, never a marketing hook.
- **Materially-rooted** — concrete numbers, real RFC IDs, real CVE
  numbers. Abstraction earns its place by reducing to specifics.

**Emotional goal**: reader feels "this person actually engaged with the
material — I can trust the curation." Not "viral content delivered."

### Aesthetic Direction

**Editorial / refined / kaer-morhen sibling.**

The site is the daily public-facing twin of an internal knowledge wiki
(kaer-morhen). It inherits that wiki's design system verbatim — same
Anthropic-aligned warm cream-ivory + terracotta editorial palette, same
six-font stack, same OKLCH dual-theme — but is distinguished by:

- **Different wordmark**: `vatt'ghern` + scribed-italic subtitle
  `jaskier's ballads` (Witcher world's bard who turns the hero's deeds
  into songs — apt metaphor for "Claude turns daily tech news into
  storied posts")
- **Different information architecture**: date-keyed timeline homepage
  rather than topic-keyed accumulation
- **One sigil today (daily-news skill)**, with room to grow

**Reference points (anchors, not copies)**:
- Anthropic.com editorial pages — warm cream-ivory, terracotta accent,
  serif-driven body, generous whitespace
- A naturalist's field notebook — recurring threads across entries,
  each entry self-contained but linked
- Marginalia + drop caps — typography that says "this was set with care"

**Anti-references**:
- NOT a Substack/Medium personal-brand blog (no bio block, no subscribe
  CTA, no follower-count widgets)
- NOT a tech-startup blog (no hero metric, no marketing-shaped homepage)
- NOT a generic SSG demo (no identical card grid, no hero icon over
  every heading, no gradient-text decoration)
- NOT terminal-aesthetic developer blog (no faux-prompt, no mono
  everywhere)
- NOT maximalist editorial-magazine (no oversized italic drop caps used
  decoratively, no broadsheet column tracking)

**Visual direction: refined minimalism with editorial typography**

The interface is NOT minimal in the "blank white square" sense. It is
minimal in the "every mark on the page is intentional" sense. Density
varies: roundup cards are tight (scan-mode), deep-stories are airy
(long-read mode). The rhythm of that density variation is the design's
voice.

### Typography (verbatim from DESIGN.md)

| Role | Family | When |
|---|---|---|
| Body Latin | Spectral | Prose, post body |
| Body CJK | LXGW WenKai TC (霞鶩文楷) | All Traditional Chinese prose |
| Display | EB Garamond | Wordmark, drop cap, dates |
| Scribed | IM Fell English Italic | Subtitles, ledes, marginalia, take-aways |
| Sans (labels/nav) | Manrope | Nav, labels, metadata, small-caps chrome |
| Code | JetBrains Mono | `<code>` `<pre>` only |

**Critical bilingual rule**: Site **chrome** is English in Manrope small
caps (`TODAY · ARCHIVE · TAGS`). Site **content** is 繁體中文 in
Spectral + 霞鶩文楷. This contrast is intentional — CJK heavy blocks for
content, Latin small caps for chrome. Don't translate chrome to CJK.

### Color (OKLCH, dual-theme)

Tokens defined in `src/static/site.css`. Same hue families across light
and dark — only lightness swaps, so identity stays intact:

- Warm neutrals (hue 65–80): `--ink`, `--ink-soft`, `--muted`, `--bg`,
  `--bg-soft`, `--line`
- Terracotta accent (hue 38): `--accent`, `--accent-text`, `--accent-hover`
- Ink-deep blue (hue 245): `--ink-deep` (wordmark subtitle, topic crumbs)
- Sage green (hue 150): `--sage`, `--sage-deep` (related / see-also marks)

**Restraint rule**: terracotta accent ≤ 10% of any given surface. The
bright `--accent` is reserved for: drop cap, medallion fill, blockquote
curly mark, mark highlight bg, year marker. Text uses `--accent-text`
(higher contrast).

**Both light and dark must work**. Dark mode is NOT the "default cool"
look — it's the late-evening reading mode. Both render the same content
faithfully; neither is decorative.

### Design Principles

1. **Content sovereignty over chrome consistency.** Each post can look
   different from each other; the site chrome is the minimum unifying
   layer. When choosing between "more chrome polish" and "more freedom
   for the post body," choose freedom for the post.

2. **Bilingual rhythm is the design.** English small-caps chrome plus
   CJK heavy prose isn't an i18n compromise — it's the typographic
   contrast that gives the site its voice. Don't homogenize either side.

3. **Editorial pacing, not feed pacing.** Posts are designed to be
   read, not scrolled past. Roundup is the index, deep-stories are the
   chapters. Whitespace, line-height (1.78), and column width
   (`min(64ch, ...)`) all serve readability over information density.

4. **Findable beats decorative.** Date, tags, archive, and (eventually)
   search are higher-priority than animations or hover ornaments. The
   site is for re-finding things.

5. **No identity inflation.** No author photo, no bio block, no
   "subscribe" CTA, no follower count. The wordmark is the project's
   name, not Tony's name. Cloudflare Web Analytics provides cookieless
   stats; nothing else tracks the reader.

### Accessibility

- WCAG AA contrast at minimum. `--accent-text` is the AA-safe terracotta
  for text; `--accent` is decoration-only.
- Dark mode is first-class, not an afterthought — token swaps via
  `[data-theme="dark"]` + inline pre-paint script (no FOUC).
- Read-tracker has manual toggle in addition to auto-mark (motion-impaired
  users can mark without scrolling).
- All inline SVG uses `currentColor` or design tokens for fills/strokes —
  no hardcoded hex, so dark mode never breaks.
- `localStorage` features (read state, theme) silently no-op when
  unavailable (private mode / quota).

### Technical Constraints

- **Eleventy 3.x SSG**, static HTML output, no client-side framework
- **Cloudflare Pages** hosts; build = `npm ci && npx @11ty/eleventy`
- **Read-tracker** is a single ~80-line IIFE in `src/static/read-tracker.js`
- **No third-party scripts** except Cloudflare's auto-injected Web
  Analytics (cookieless)
- All fonts self-hosted via `@fontsource` (passthrough from
  `node_modules/@fontsource/*` to `_site/static/fonts/`)
- HTML lint via `html-validate` (PR-time check)
- Custom tests: `tests/archetype-check.mjs` enforces archetype rules,
  `tests/link-check.mjs` verifies internal links
