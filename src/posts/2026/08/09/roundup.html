別再填 JSON，讓模型寫程式

這篇把兩種工具呼叫介面放到同一把尺上量：一種是原生的 JSON tool calling，另一種是把工具寫成帶型別的 Python stub、讓模型用程式碼去呼叫，執行與取回結果都在同一個 agent turn 內完成。在 BFCL v4 上跨 14 個模型比較，programmatic tool calling 在其中 11 個追平或勝出，GPT-5.6 家族相對 JSON 基準線是 10.6% 的改善。兩個邊界條件把差距拉得更開：平行 fan-out 時 13 個模型追平或勝出，而在 context rot 條件下基準線平均退化 2.3%，程式碼那條路維持穩定。

一道指令，跑六十二秒

指令延遲分析通常是為了最佳化，這個 repo 把方向倒過來，去找單一指令效能的絕對地板：setup 隨你怎麼鋪，但只有一道指令列入計分，時間以 CPU base clock 正規化，硬體必須是原廠出廠狀態。榜上的每一筆都對應一個具體的微架構理由——idiv 用 128 位元被除數把除法器的 microcode 走滿是 77 cycles，mfence 在 write-combining buffer 塞滿時是 326 cycles，rdrand 在熵池耗盡時是 5,579 cycles，Zen 上對 MCG_CTL 下 wrmsr 是 34,304 cycles。冠軍是 fxrstor64：512 位元組的狀態從高延遲 MMIO 載入，同時用其他核心把 PCIe root complex 打滿，量到 198,002,498,236 cycles，也就是 62 秒。

#02

從門鈴走進你家內網

研究者把 Eufy 視訊門鈴與 HomeBase Station 2 的整條鏈打通：先靠 90:bf:d9 這個 OUI 掃出 HomeBase，送 500 個廣播 deauth 把門鈴踢離 HomeBase 的隱藏網路，影像改成只錄在本機、不再上傳；再從 dump 出來的韌體逆出用聲波傳配對憑證的協定，19 個頻率、150 Hz 間距、每個符號約 65 到 70 毫秒，前段用 Reed-Solomon、最後一段用 CRC-16；最後用 Raspberry Pi 接上測試點，透過 SPI0 把門鈴的快閃記憶體讀出來。真正致命的是金鑰推導：一段寫死的 64 位元組字串與 0x01、0x04、0x06 的重複樣式 XOR 之後取 MD5，就是解開 es_config 的 AES-128-ECB 金鑰；因為推導過程全靠寫死的資料，作者判斷這把金鑰在各裝置間應該是同一把。

#04

網域可以在 DNS 裡說自己要賣

RFC 10023 定義了一筆放在 _for-sale 底下的 TXT 記錄，格式從 v=FORSALE1 這個版本標籤開始，後面帶 ftxt、furi、fval 或 fcod 其中一個。它解的是規格書自己講的那個缺口：願意賣的人沒有辦法讓有興趣的買家知道，除非對方寄冷信給多半已被隱私遮蔽移除的 WHOIS 聯絡人。和停放頁不同的地方在於它不取代任何東西，「首頁繼續服務，郵件繼續流動」，靠的是 RFC 8552 的底線節點命名慣例，TTL 建議壓在 3600 秒以內。規格也直說沒簽 DNSSEC 的記錄「是別人偽造起來很舒服的東西」，而 ftxt 與 furi 都是攻擊者可控的內容，顯示前要消毒。

讓網站自己長出 agent 介面

WebMCP 是「一個新的瀏覽器標準，在 Chrome 146 實驗性推出，在頁面裡以 document.modelContext 出現」，網站用 registerTool() 註冊工具，型別直接沿用 MCP 自己的 Tool 與 CallToolResult。Cloudflare 這一側的實作只有一個開關：打開之後用 HTMLRewriter 在每份 HTML 回應裡插一行 bridge script 的參照，origin 完全不用改。安全邊界寫得清楚——這個預覽版裡「每個工具都完全跑在訪客的瀏覽器裡，不會繞到我們的伺服器」，要接自家 MCP server 時也是從頁面上用訪客既有的 session 直連。差別在於 agent 不必再從給人看的頁面猜路，token 花在任務而不是導覽上。

每一跳都合法，整條路徑不合法
