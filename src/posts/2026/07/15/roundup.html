Meta 廣告換上 sched_ext：p99 延遲砍 28%

Meta 升級到 Linux 6.9 後，新的 EEVDF 排程器讓廣告服務出現延遲回退，逼得部分伺服器卡在舊的 6.4 kernel。他們最後導入 sched_ext——一套 BPF-based、6.12 正式進 kernel 的可擴充排程框架——把 CPU 軟性切成延遲敏感與背景兩池，首發就讓廣告檢索階段 p99 延遲降 28%、全機隊省下 3.28 百萬瓦電力。後續兩次 user-space 策略更新「以天為單位而非月」再砍 60% p99，靠的是不用重編 kernel 就能改排程政策。

分支預測殺手：branchless 二分搜尋快 6.5 倍

一般二分搜尋在資料均勻分布時 CPU 幾乎無法預測分支走向，作者實測有 16.6% 的分支誤預測。改用 select_unpredictable() 做 branchless 版本、把迴圈次數固定成 log₂ 並用 cmov 取代 if 之後，Rust 實作從 45,981 微秒降到 7,106 微秒，快了 6.5 倍。作者一句話總結：「分支誤預測完全消失了。」

#05

一個「沒用的 if」讓迴圈快四倍

作者在一個緊湊迴圈裡加了看似多餘的 if (j != next_j[i][j])，合成測試中迴圈從 320 微秒降到 80 微秒、快了四倍（真實情境約兩倍）。訣竅在於 CPU 會把這個 if 分支預測成不會發生，於是不再認為相鄰迭代之間有資料相依，得以把 iteration 平行化——一個反直覺但可複製的 mechanical sympathy 技巧。
