# zh-TW Prose 規範 — 中文文字品質

寫給每一個產出中文 prose 的 agent：roundup lede、deep-story 正文、
sidecar `summary`、`data-mobile-summary`、weekly/monthly rollup。這份
檔案管「文字本身」——AI 套話、黑話、翻譯腔、節奏、台灣用語。結構、
選題、材料密度歸 archetype 規範與 rubric Axis 1-7 管。

規則萃取自 stop-slop-zh-tw、yelban/humanizer.TW、
kevintsai1202/Humanizer-zh-TW 三個開源專案（概念借鑑、文字重寫），
依本站人設過濾——與上游的明確分歧集中在 §8，遇到衝突以本檔為準。

## 1. 鐵律——不得捏造

去 AI 味的手段只有兩種：**刪除**與**改寫**。

所有具體數字、場景、引語、人名、案例必須來自 source 材料。上游
humanizer 系 skill 的範例常用「補一個具體場景」來修空泛句（「上週給
三家客戶試用，兩家說好」）——在新聞站這叫捏造。空泛句的正確修法：

- source 裡有依據 → 換成 source 裡的具體事實（數字、RFC 編號、
  commit、引語）
- source 裡沒有 → 整句刪掉

## 2. 開場與結尾套話（Step 8 機械掃描會擋）

以下出現即 fail，`check-zh-prose.mjs` 與本節同步：

- 時代開場：「隨著…的發展／興起／普及／演進」「在當今／這個…時代」
  「在…的浪潮中」
- 共識開場：「眾所周知」「不言而喻」「毋庸置疑」
- 宣告開場：「值得注意的是」「值得一提的是」「值得關注的是」
  「不難發現」
- 總結套話：「綜上所述」「總而言之」
- 結尾套話：「讓我們拭目以待」「未來可期」「攜手共進」「開啟…新篇章」
  「值得我們深思」

修法：刪掉，從事實開始講。結尾用具體的後續事實收（下個版本、未解的
限制、已排定的時程），不用展望口號。

## 3. 連接詞減量

「此外」「與此同時」「不僅如此」「首先…其次…最後」大量刪減——段落
之間的邏輯靠內容自己接，不靠路標。自然轉折詞（「但是」「不過」）是
**減量對象，不是禁語**：中文沒有它們寫不下去，但每個轉折都掛一個就
是公式腔。

編號式展開（「第一…第二…第三」）改成自然過渡：「一個是…另一個
是…」「先…再…」，或直接讓三件事各成一段。

## 4. 互聯網黑話

高信心子集（賦能、抓手、閉環、打法、顆粒度）機械掃描會擋；下表其餘
由 reviewer Axis 8 把關：

| 避免 | 改用 |
|------|------|
| 賦能 | 幫助、支援、讓…能 |
| 抓手 | 切入點、方法 |
| 閉環 | 完整流程；控制理論用「閉迴路」 |
| 打法 | 做法、策略 |
| 顆粒度 | 粒度、細緻程度 |
| 痛點 | 問題、困難 |
| 落地 | 實作、上線、導入 |
| 賽道 | 領域、市場 |
| 沉澱 | 累積、整理 |
| 對齊（進度／認知） | 同步、確認一致 |
| 心智（用戶心智） | 認知、印象 |

技術名詞保留英文：io_uring、CRDT、RFC、Agent、MCP、token、commit。
不硬翻。

## 5. 翻譯腔

- **「的」字堆疊**：連續超過兩個「的」就重寫。「我們公司的產品設計
  部門的資深設計師的作品」→「我們設計部資深設計師的作品」。
- **被動句**：「被」字句多半是英文 passive 直譯。「這個方案被採納
  了」→「團隊採納了這個方案」。找出做動作的人，放回主詞。
- **「這是一個…的」框架**：「這是一個很重要的決定」→「這個決定很
  重要」。
- **「進行＋動詞」**：「進行優化」→「優化」；「對效能進行測試」→
  「測效能」。
- **歐化句架**：「對於…而言」「在…的情況下」「使得」「…之一」——
  念出來像翻譯字幕就改。「對於開發者而言這使得除錯變得困難」→
  「開發者因此更難除錯」。

## 6. 普遍性 AI patterns

- **誇大意義**：「標誌著」「彰顯了」「見證了」「為…奠定基礎」「在
  …中扮演關鍵角色」——直接說那件事是什麼、做了什麼。
- **模糊歸因**：「業界普遍認為」「專家指出」——修法是**引具體來源**
  （誰、哪份報告、哪個 thread），不是刪掉歸因改成斷言。這條與
  rubric Axis 3（material grounding）同向。
- **否定式排比**：「不僅僅是 X，更是 Y」「不是 X，而是 Y」——直接
  講 Y。
- **三段式法則**：AI 偏好把任何列舉湊成三項。兩項或四項常常更誠實；
  發現自己在湊第三項就停。
- **同義詞循環**：「主人翁→主要角色→中心人物→英雄」——重複用同
  一個詞比機械換詞自然。技術名詞尤其不要換著叫。
- **虛假範圍**：「從 X 到 Y」要在同一個有意義的尺度上。「從 kernel
  bypass 到開發者體驗」不是一個尺度。
- **金句結尾**：每段結尾來一句可引用的總結是 AI 的招牌。段落收在
  事實上即可。

## 7. 節奏

- **長短句交替**。連續三句等長就拆一句。短句有力。長句讓一個複雜的
  機制在同一口氣裡講完，兩種都要有。
- **段落結尾多樣化**：不要每段都用總結句收。可以收在數字、引語、
  未解的問題上。
- **三秒檢測法**：把任何一句遮起來，上下文還接得起來，這句就是
  填充物，刪掉。塑膠句會換皮（「展現了→彰顯了→印證了」是同一個
  模式），抓「主詞換成別人也成立」這個本質。

## 8. 語氣校準——與上游 humanizer 的明確分歧

上游三個專案都把「口語化」當解藥（「進行討論」→「聊一下」、鼓勵
第一人稱聊天感、「允許混亂」）。本站不採用。人設是 measured senior
tech lead（見 persona.md）：書面、節制、材料紮實——去掉的是 AI 套話，
不是書面語本身。

- **維持書面 register**。「我跟你說」「太離譜了」「給人整不會了」
  這類口語填充詞在本站是反模式，不是人味。
- **稱讀者「你」，不用「您」**。
- **標點是本站慣例，不採上游禁令**：CJK 全形冒號「：」做標籤／定義、
  CJK 雙破折號「——」做插入語，照 persona.md 用。上游「禁冒號、禁
  破折號」的規則來自簡中自媒體語感，與本站排版系統衝突。
- **不裝個性**。上游教「注入靈魂」（加感嘆、加自嘲、加題外話）——
  本站的人味來自判斷與材料（誠實的 hedge、具體的數字、敢給結論），
  不來自表演性的情緒。
